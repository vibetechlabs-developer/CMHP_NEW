CMHP ERP — User Guide

Follow your role, complete each step, and verify your work.

This is a guide. Actions here do not change ERP records.

Permissions, not role names, actually control access. The role filter above only hides or shows guide steps for readability — it changes nothing in the real application. Status badges: Website available Setup team / API only Not implemented Needs confirmation

A. Start Here

A short map before you begin. Each numbered item links to its full section.

If this is a brand-new installation

  1. A Setup Administrator completes B. First-Time Setup once. Most of it is command-line or API work — ask your setup administrator if you are not that person.
  2. Business Admin creates customers and products: C. Customers & Products.
  3. Someone with catalog access sets up shared materials: D. Shared Store & Materials.
  4. A formula is drafted and approved: E. Formulas & Revisions.
  5. The daily three-department order flow begins: F → G → H.

If setup is already done and you just need to place an order

Go straight to F. Admin — Create Order.

What "Website available" really means

"Website available" means the screen is connected to the real backend in the application's source code. It does not mean someone has clicked through it in a browser to confirm the screen renders correctly on your machine. Treat it as "built and wired up," not as "already visually verified today."

A brand-new superuser has zero company memberships, so none of that appears yet — not even the User Management screen you would normally use to assign memberships to other people. The very first membership, for your own account, has to be created this one time through the API.

Your own user id (from the current-user call) and one of the company ids from B2.

B8. Units of measure and product types

Setup team / API only — no creation screen exists
Why this matters to ordinary users
The Materials and Products forms only let you search active units and product types — they cannot create new ones. If this step is skipped, the unit search box in Materials/Products will simply find nothing, and the Product Type dropdown will only offer "Not specified."
Expected result
At least one unit per dimension you need (e.g. a mass unit, a count unit) and at least one product type exist and are active.
Technical details
Create a unitPOST /api/v1/units/ body {"code": "KG", "name": "Kilogram", "dimension": "MASS"} — dimension is one of MASS, VOLUME, COUNT
Optional conversion factorcanonical_factor on the same call — becomes immutable once set
Create a product typePOST /api/v1/product-types/ body {"name": "<Type Name>"}

B9. Decide the formula approval policy

Setup team / API only — unanswered business decision
Why you must decide this, not skip it
With no policy configured, every approval attempt is refused — not "approval is open by default." Approval stays blocked company-wide until someone explicitly answers this.
The decision
Allow self-approval — whoever drafted or edited a revision may also approve it. Simpler for a small team, but weaker separation of duties.
Do not allow self-approval — a different, real person must approve. You then need a second account with formulas.approve who did not contribute to that revision, or nothing can ever be approved.
Next step
C and D — master data; then E — formulas, which depends on this policy to approve anything.
Technical details
Method / pathPATCH /api/v1/companies/<company_id>/formula-approval-policy/
First-time body{"expected_version": 0, "allow_self_approval": true} (or false) — 0 only on the very first time

C2. Create a product

Business Admin (needs products.view and products.create)
Where to go
Sidebar → Products → + Add product

The product appears in the list.

C3. Import customers or products from a CSV file

Website available
Where to go
Customer Management → Import CSV, or Products → Import CSV
Action
Choose the file, then Check file — this only validates, nothing is saved yet. Review every row's result. Only once every row is valid does Import become available.
Expected result
Customer import is all-or-nothing on commit: if any row is invalid, nothing is created and you fix the file and check again. Product import works the same way, but also keeps a server-side "preview" copy: if you wait too long or someone else changes things, the commit is refused as stale and you simply choose the file again and re-check it.
Save / reopen / refresh check
After a successful import, reload the list — the new rows are there.
Next step
C1/C2's individual next steps.
Common problem: "This import changed since it was checked" (products only) — the preview expired or was already used. Choose the file again and press Check file before importing.

D. Shared Store & Materials

One shared material catalog, used by both companies. One physical shared store. Creating or importing a material never creates any stock — it only defines what the material is.

Website available
Where to go
Top bar → workspace switcher → Common Inventory
Expected result
Sidebar now shows Store & Materials with Materials, Locations and Recorded Receipts. This group is hidden under the Company A/B workspaces, and the company screens (Orders, Products…) are hidden here — switch back and forth as needed.

D2. Create a material

Website available
Who performs it
Whoever holds catalog-write access (an active superuser today — see N for the exact rule)
Where to go
Store & Materials → Materials → + Add material
What to enter
Material code, Material name, Type (Raw material / Packaging), Base unit (search — only finds units already created in B8), Description (optional).
Expected result
The material appears in the list, Active by default.
Save / reopen / refresh check

Next step

Common problem: if you do not see + Add material at all, your account does not have catalog-write access — the page is read-only for you. Ask your setup administrator.

D3. Import materials from a CSV file

Website available
Where to go
Materials → Import materials → Download template first
What to enter
Columns: code, name, material_type (RAW or PACKAGING), base_unit_code, description
Action
Choose the filled-in file → Check file (preview, writes nothing) → review every row → Import N materials (all-or-nothing)
Expected result
Either every valid row is created, or nothing is, with a specific reason per invalid row.
Save / reopen / refresh check
Reload Materials and confirm the new codes are present.

D4. Storage locations

Website available, read-only today
Where to go
Store & Materials → Locations
Current limitation
This screen lists locations for your store; it does not create or edit them in the website yet (API only). More importantly: a goods receipt does not record which location a material was placed in — do not treat anything shown here as proof of physical placement.

D5. Recorded Receipts

Website available, read-only
Where to go
Store & Materials → Recorded Receipts
What it shows
Quantities labelled exactly "Recorded receipt quantity", grouped by material, unit and source company. This is never "available", "released", "on-hand" or "usable" stock — none of those concepts exist in this system yet.
Source company
Shown as receiving/purchasing context only — it is not a legal-ownership statement, and a shared store does not establish ownership by itself.
Coverage notice
A fixed banner explains: opening stock, issues, returns and QC release are not included.

Next step

E2. Add material lines and save the draft

Website available
Where to go
The formula editor, open the revision, + Add material under Raw Materials or Packaging Materials
What to enter
Base quantity per line, and optionally Special value, Label claim, AR No.
Action

Expected result
A visible "saved"/"unsaved" indicator; after saving it reads as saved.
Save / reopen / refresh check
Close and reopen the revision — every line and value is still there.
Next step
E3 — a new revision if you need another draft, or E4 to approve this one.

E3. Start a new revision

Website available
Action
+ New revision
Expected result
Always starts completely empty. Nothing is copied from the previous revision, approved or not — this was verified directly in today's code. There is also no "use the latest approved revision automatically" behaviour anywhere; every revision choice is explicit.

E4. Check approval, then approve

Website available (needs the policy from B9)
Who performs it
An account with formulas.approve
Where to go
The formula editor's Approval panel, below the material tables
Action
Check approval first (shows exactly why approval would or would not succeed), then, only if eligible, Approve revision N
The self-approval rule, exactly
If the company policy does not allow self-approval, the approver must not be a contributor to this specific revision — meaning they did not draft or edit it. This is checked by the server, not just hidden in the interface.
Expected result
The revision becomes APPROVED and permanently read-only — not even an account with formulas.edit can change its lines again.
Save / reopen / refresh check
Reopen the approved revision; every editing control is gone.
Common problem: "The company policy does not allow someone who created or changed this revision to approve it" — this is expected when self-approval is disallowed. You need a second, uninvolved account with formulas.approve.

E5. Unsaved input is kept when you open and close the formula drawer

Website available
Where this matters
While filling in an order's batch section, you can open Manage formulas to check or edit a formula, then close it and return to the order.
Expected result
Whatever you had typed into the batch section, but not yet saved, is still there when you come back.

H3. Enter batch output, packing relationship and printing fields

Website available
What to enter
Target output quantity and its unit (the formula's own output unit); Planned manufacturing date; MRP for printing; Printing status (free text).
About the packing relationship
By default, the product's sales unit must equal the formula's output unit. If they differ, you must supply all three packing fields together — planned pack quantity, packing content quantity, and packing content unit — never just one or two. Supplying only part of the relationship is refused with a message naming exactly which field is missing.
Review
The Material Requirements preview (Section's own calculator, same as E) shows what this target output actually needs, computed by the server.
Action
Save batch plan
Save / reopen / refresh check
Reopen and refresh; every value persists.

H4. Explicitly allocate the official batch number

Website available
Action
Allocate batch number — a separate, deliberate button, never automatic
Format
CODEYY-NNN — the customer's code (never the operating company's own code), the two-digit allocation year, and a sequence that restarts at 001 every year, per customer. Example: NOVA26-001.
Expected result
The number appears on the order.
Save / reopen / refresh check
Reopen the order — the same number is shown. Allocating again for the same plan returns the identical number, never a new one.

What this journey does not require

Order confirmation is a separate, optional feature. The current planning flow creates and saves batch plans directly from a DRAFT order line — do not treat "confirm the order" as a mandatory step before Store Preparation or Batch Planning, because the code does not require it.

L. Troubleshooting

ProblemWhat it meansWhat to do
No company workspace availableYour account has no company membership yet.Ask your setup administrator to assign one (Section B6/B4). Do not ask for broader access than your role needs.
